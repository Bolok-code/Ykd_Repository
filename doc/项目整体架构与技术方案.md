## 1. 项目概述

### 1.1 项目定位

**YKD Bot** 是一个基于 Spring Boot 和 Spring AI 构建的**多模态智能助手平台**，通过微信 iLink SDK 为用户提供：

- 💬 **AI 对话**: 支持文本、图像、语音多模态交互
- 📄 **文档处理**: PDF/Word/Excel 解析与知识库管理
- 💼 **智能求职**: 猎聘自动化投递与岗位匹配
- 🌤️ **生活助手**: 天气查询、位置服务、定时提醒
- 🎨 **内容生成**: 图片、视频、语音合成

### 1.2 核心价值

1. **统一入口**: 微信作为唯一交互界面，用户无需安装额外应用
2. **智能编排**: Spring AI Function Calling 自动选择合适工具
3. **记忆持久化**: SQLite 保存对话历史,支持上下文压缩
4. **自动化流程**: 猎聘求职助手实现简历匹配→搜索→投递全流程
5. **知识增强**: RAG 检索增强生成,基于用户文档回答问题

### 1.3 技术亮点

| 技术点 | 实现方式 | 优势 |
|--------|----------|------|
| 多模态 AI | Agnes Vision + DeepSeek | 图文混合理解,成本可控 |
| 浏览器自动化 | Playwright Java API | 持久化登录,支持无头模式 |
| 向量检索 | DashScope Embedding + 余弦相似度 | 高精度语义搜索 |
| 并发控制 | 按用户串行队列 | 保证对话顺序,避免竞态 |
| 热更新 | Skill 系统 | 无需重启即可调整 AI 行为 |

##### 核心实现

**LlmServiceImpl.chat() 方法**

```java
public String chat(String text, List<String> imageUrls, 
                   ChatClient client, String userId, 
                   String systemContext) {
    
    // 1. 加载对话历史
    List<Message> history = memoryManagerService.getHistory(userId);
    
    // 2. Skill 路由 (仅针对纯文本)
    Optional<SkillDefinition> selectedSkill = 
        hasImages ? Optional.empty() : skillSelector.select(text);
    
    // 3. 构建请求消息列表
    List<Message> requestMessages = new ArrayList<>(history);
    
    // 4. 注入系统上下文 (RAG 检索到的文档内容)
    if (systemContext != null) {
        requestMessages.add(new SystemMessage(systemContext));
    }
    
    // 5. 启用 Skill (覆盖默认系统提示词)
    selectedSkill.ifPresent(skill -> {
        requestMessages.add(0, new SystemMessage(buildSkillPrompt(skill)));
    });
    
    // 6. 注册工具
    ChatClient.ChatClientRequestSpec requestSpec = client.prompt()
        .messages(requestMessages)
        .user(userSpec -> {
            userSpec.text(text);
            if (hasImages) {
                for (String url : imageUrls) {
                    userSpec.media(new Media(
                        MimeTypeUtils.IMAGE_JPEG, 
                        URI.create(url)
                    ));
                }
            }
        });
    
    // 7. 工具限流
    if (selectedSkill.isPresent()) {
        // Skill 模式: 只暴露 Skill 指定的工具
        ToolCallback[] skillTools = skillToolResolver.resolve(skill);
        requestSpec.tools((Object[]) skillTools);
    } else {
        // 普通模式: 暴露除猎聘外的所有工具
        requestSpec.tools(weatherTools, locationTools, imageTools, ...);
    }
    
    // 8. 调用模型
    ChatResponse chatResponse = requestSpec.call().chatResponse();
    String content = chatResponse.getResult().getOutput().getText();
    
    // 9. 保存对话历史
    memoryManagerService.save(userId, text, content, modelName);
    
    // 10. 自动压缩上下文 (超过 6000 token)
    Usage usage = chatResponse.getMetadata().getUsage();
    if (usage != null) {
        memoryManagerService.compressIfNeeded(userId, usage.getPromptTokens());
    }
    
    return content;
}
```

```
  - 批量调用 DashScope text-embedding-v3
  - 每个片段生成 1024 维向量
  ↓
保存到 knowledge_chunk 表
  - chunk_index, content, embedding (JSON)
  ↓
更新文档状态为 COMPLETED
```

**2. 检索流程**

```
用户提问: "如何配置猎聘自动投递?"
  ↓
EmbeddingService.embed(question)
  - 生成问题向量
  ↓
RagRetrievalService.retrieve()
  - 查询用户所有文档片段
  - 计算余弦相似度
    similarity = dot(v1, v2) / (||v1|| * ||v2||)
  - 过滤低于阈值的结果 (默认 0.0)
  - 按相似度降序排列
  - 取 Top-K (默认 5)
  ↓
formatContext(results)
  - 拼接成提示词
  - 限制总字符数 (默认 6000)
  ↓
注入到 LlmService.chat() 的 systemContext 参数
  ↓
DeepSeek 基于检索内容回答
```

```yaml
  max-context-chars: 6000      # 上下文总字符数上限
  similarity-threshold: 0.0    # 相似度阈值
```

##### 向量计算

**余弦相似度实现**

```java
public double cosineSimilarity(float[] vec1, float[] vec2) {
    double dotProduct = 0.0;
    double norm1 = 0.0;
    double norm2 = 0.0;
    
    for (int i = 0; i < vec1.length; i++) {
        dotProduct += vec1[i] * vec2[i];
        norm1 += vec1[i] * vec1[i];
        norm2 += vec2[i] * vec2[i];
    }
    
    return dotProduct / (Math.sqrt(norm1) * Math.sqrt(norm2));
}
```

**特点**:
- 值域: [-1, 1],1 表示完全相同
- 不受向量长度影响,只看方向
- 高维空间表现良好

```java
}
```

##### 关键方法

**1. getHistory() - 惰性加载**

```java
public List<Message> getHistory(String userId) {
    hydrateFromDatabaseIfNeeded(userId);
    return chatMemory.get(userId);
}

private void hydrateFromDatabaseIfNeeded(String userId) {
    if (hydratedUsers.contains(userId)) return;
    
    Object lock = hydrationLocks.computeIfAbsent(userId, k -> new Object());
    synchronized (lock) {
        // 双检锁避免重复加载
        if (hydratedUsers.contains(userId)) return;
        
        List<Message> messages = conversationHistoryService
            .findAllMessages(userId)
            .stream()
            .map(this::toSpringAiMessage)
            .toList();
        
        chatMemory.add(userId, messages);
        hydratedUsers.add(userId);
    }
}
```

**2. save() - 双写**

```java
public void save(String userId, String userText, 
                 String assistantReply, String modelName) {
    
    // 写入 SQLite
    conversationHistoryService.saveTurn(
        userId, userText, assistantReply, modelName
    );
    
    // 写入内存
    chatMemory.add(userId, List.of(
        new UserMessage(userText),
        new AssistantMessage(assistantReply)
    ));
}
```

**3. compressIfNeeded() - 自动压缩**

```java
public void compressIfNeeded(String userId, int promptTokens) {
    List<Message> history = chatMemory.get(userId);
    
    if (promptTokens < COMPRESS_THRESHOLD_TOKENS) return;
    
    // 从后往前保留最近 2500 token
    int splitIndex = findSplitIndex(history, KEEP_RECENT_TOKENS);
    
    List<Message> toCompress = history.subList(0, splitIndex);
    List<Message> recent = history.subList(splitIndex, history.size());
    
    // 调用 LLM 生成摘要
    String summary = summaryClient.prompt()
        .messages(toCompress)
        .call()
        .content();
    
    // 替换历史
    conversationHistoryService.replaceHistory(userId, summary, recent);
    
    chatMemory.clear(userId);
    List<Message> replacement = new ArrayList<>();
    replacement.add(new AssistantMessage("[对话摘要] " + summary));
    replacement.addAll(recent);
    chatMemory.add(userId, replacement);
}
```

| 特性 | 实现 | 优势 |
|------|------|------|
| 双存储 | SQLite + ChatMemory | 重启不丢失,查询高效 |
| 惰性加载 | 首次对话才从 DB 加载 | 降低内存占用 |
| 自动压缩 | LLM 生成摘要 | 无限对话不爆内存 |
| 按用户锁 | ConcurrentHashMap<String, Object> | 避免并发冲突 |

```java
private ParseResult parsePdf(byte[] bytes) throws IOException {
    try (PDDocument document = Loader.loadPDF(bytes)) {
        PDFTextStripper stripper = new PDFTextStripper();
        String text = stripper.getText(document);
        
        // 文本内容不足 50 字,判断为扫描版
        if (text.trim().length() < 50) {
            text = ocrPdfWithAi(document);  // Agnes Vision OCR
        }
        
        return new ParseResult("PDF", document.getNumberOfPages(), text);
    }
}

private String ocrPdfWithAi(PDDocument document) throws IOException {
    PDFRenderer renderer = new PDFRenderer(document);
    StringBuilder ocrText = new StringBuilder();
    
    for (int i = 0; i < document.getNumberOfPages(); i++) {
        BufferedImage image = renderer.renderImageWithDPI(i, 200);
        
        // 转 Base64 发送给 Agnes
        String base64 = imageToBase64(image);
        String dataUri = "data:image/png;base64," + base64;
        
        String pageText = ocrClient.prompt()
            .user(userSpec -> userSpec
                .text("提取图片中的所有文字")
                .media(new Media(MimeTypeUtils.IMAGE_PNG, URI.create(dataUri))))
            .call()
            .content();
        
        ocrText.append(pageText).append("\n\n");
    }
    
    return ocrText.toString();
}
```

### 5.1 Spring AI Function Calling

#### 5.1.1 原理

Spring AI 通过 `@Tool` 注解自动将 Java 方法转换为 OpenAI 风格的 `function` 定义:

```java
@Component
public class WeatherTools {
    
    @Tool(description = "查询天气信息。支持实时天气和未来预报。")
    public String getWeather(
```

### 5.3 对话上下文压缩

#### 5.3.1 问题

- LLM 输入长度限制 (DeepSeek v4-pro: 64K tokens)
- Token 越多,响应越慢,成本越高
- 用户长时间对话会超出限制

#### 5.3.2 解决方案

**触发条件**: `promptTokens >= 6000`

**压缩策略**:
1. 从后往前保留最近 `2500 token` 的消息
2. 前面的消息调用 LLM 生成摘要
3. 用摘要替换旧消息

**实现**:
```java
// 1. 找到分割点
int keepTokens = 0;
int splitIndex = history.size();
for (int i = history.size() - 1; i >= 0; i--) {
    keepTokens += estimateTokens(history.get(i));
    if (keepTokens >= KEEP_RECENT_TOKENS) {
        splitIndex = i;
        break;
    }
}

// 2. 分割历史
List<Message> toCompress = history.subList(0, splitIndex);
List<Message> recent = history.subList(splitIndex, history.size());

// 3. 生成摘要
String summary = summaryClient.prompt()
    .messages(toCompress)
    .call()
    .content();

// 4. 替换历史
chatMemory.clear(userId);
List<Message> replacement = new ArrayList<>();
replacement.add(new AssistantMessage("[对话摘要] " + summary));
replacement.addAll(recent);
chatMemory.add(userId, replacement);

// 5. 同步到 SQLite
conversationHistoryService.replaceHistory(userId, summary, recent);
```

**效果**:
- 用户可以无限对话
- 旧对话通过摘要保留关键信息
- 新对话保持完整上下文

### 5.4 RAG 检索流程

#### 5.4.1 文本分块 (Chunking)

```java
public List<String> split(String text, int chunkSize, int overlap) {
    List<String> chunks = new ArrayList<>();
    int start = 0;
    
    while (start < text.length()) {
        int end = Math.min(start + chunkSize, text.length());
        chunks.add(text.substring(start, end));
        start += chunkSize - overlap;
    }
    
    return chunks;
}
```

**配置**:
- `chunk-size: 600` (字符)
- `chunk-overlap: 100` (重叠区域)

**为什么需要 overlap?**
- 避免语义被切断
- 提高检索召回率

**示例**:

```
Chunk 2: "...集成了 OpenAI、DeepSeek 等多个模型,支持 Function Calling 和..."
```

### 5.5 并发控制

#### 5.5.1 问题

- 同一用户的消息乱序处理会导致上下文错乱
- 全局串行处理会降低多用户场景吞吐量

#### 5.5.2 解决方案

**按用户串行,跨用户并行**:

```java
@Component
public class PerUserTaskDispatcher {
    
    private final Map<String, ExecutorService> userExecutors = 
        new ConcurrentHashMap<>();
    
    public void submit(String userId, Runnable task) {
        ExecutorService executor = userExecutors.computeIfAbsent(
            userId, 
            k -> Executors.newSingleThreadExecutor(r -> {
                Thread t = new Thread(r, "user-" + userId);
                t.setDaemon(true);
                return t;
            })
        );
        executor.submit(task);
    }
}
```

**效果**:

| 场景 | 处理方式 |
|------|----------|
| 用户 A 发送消息 1 | 进入 `user-A` 线程 |
| 用户 A 发送消息 2 | 排队等待消息 1 处理完 |
| 用户 B 发送消息 1 | 进入 `user-B` 线程 (并行) |

**内存清理**:
```java
@PreDestroy
public void shutdown() {
    userExecutors.values().forEach(executor -> {
        executor.shutdown();
        try {
            executor.awaitTermination(10, TimeUnit.SECONDS);
        } catch (InterruptedException e) {
            executor.shutdownNow();
        }
    });
}
```

```java
    // 去除 Markdown 语法
    text = text.replaceAll("^#+\\s+", "");  // 标题
    text = text.replaceAll("\\*\\*(.+?)\\*\\*", "$1");  // 加粗
    text = text.replaceAll("\\*(.+?)\\*", "$1");  // 斜体
    text = text.replaceAll("\\[(.+?)\\]\\(.+?\\)", "$1");  // 链接
    
    return new ParseResult("Markdown", 1, text);
}
```

**2. 测试**

```
解析文本 → 分块 → 向量化 → 入库
  ↓
用户: "项目如何启动?"
```

**4. 配置工具解析器**

```java
@Component
public class SkillToolResolver {
    
    private final HotelTools hotelTools;  // 注入
    
    public ToolCallback[] resolve(SkillDefinition skill) {
        return switch (skill.name()) {
            case "liepin-auto-apply" -> resolveLiepinTools(skill);
            case "hotel-booking" -> resolveHotelTools(skill);  // ← 新增
            default -> new ToolCallback[0];
        };
    }
    
    private ToolCallback[] resolveHotelTools(SkillDefinition skill) {
        return skill.tools().stream()
            .map(tool -> switch (tool) {
                case "searchHotels" -> ToolCallback.from(
                    "searchHotels", hotelTools::searchHotels
                );
                case "bookHotel" -> ToolCallback.from(
                    "bookHotel", hotelTools::bookHotel
                );
                default -> null;
            })
            .filter(Objects::nonNull)
            .toArray(ToolCallback[]::new);
    }
}
```

**1. ChatMemory 迁移到 Redis**

```java
@Configuration
public class ChatMemoryConfig {
    
    @Bean
    public ChatMemory chatMemory(RedisTemplate<String, Object> redisTemplate) {
        return new RedisChatMemory(redisTemplate);
    }
}

@Component
public class RedisChatMemory implements ChatMemory {
    
    private final RedisTemplate<String, Object> redisTemplate;
    
    @Override
    public void add(String conversationId, List<Message> messages) {
        String key = "chat:memory:" + conversationId;
        redisTemplate.opsForList().rightPushAll(key, messages);
        redisTemplate.expire(key, 7, TimeUnit.DAYS);
    }
    
    @Override
    public List<Message> get(String conversationId) {
        String key = "chat:memory:" + conversationId;
        return redisTemplate.opsForList()
            .range(key, 0, -1)
            .stream()
            .map(obj -> (Message) obj)
            .toList();
    }
}
```

**2. 定时任务分布式锁**

```java
@Scheduled(fixedDelayString = "${liepin.auto-apply.scan-interval-ms:60000}")
public void scan() {
    String lockKey = "lock:liepin:scan";
    boolean acquired = redisTemplate.opsForValue()
        .setIfAbsent(lockKey, "1", 60, TimeUnit.SECONDS);
    
    if (!acquired) {
        log.debug("[LiepinJob] 其他实例正在执行扫描,跳过");
        return;
    }
    
    try {
        taskManager.scanAutomaticCampaigns();
    } finally {
        redisTemplate.delete(lockKey);
    }
}
```

### 7.6 性能优化

#### 7.6.1 批量向量化

**当前**:
```java
for (String chunk : chunks) {
    String embedding = embeddingService.embed(chunk);
    chunkMapper.insert(chunk, embedding);
}
```

**优化**:
```java
List<String> embeddings = embeddingService.embedBatch(chunks);
chunkMapper.batchInsert(chunks, embeddings);
```

**收益**: API 调用次数从 N 次降到 1 次

#### 7.6.2 向量索引

**当前**: 全表扫描计算相似度

**优化**: 使用 pgvector 扩展

```sql
CREATE EXTENSION vector;

ALTER TABLE knowledge_chunk 
ADD COLUMN embedding vector(1024);

CREATE INDEX ON knowledge_chunk 
USING ivfflat (embedding vector_cosine_ops);
```

```java
// 使用 pgvector 的 KNN 查询
@Select("""
    SELECT *, embedding <=> #{queryEmbedding}::vector AS distance
    FROM knowledge_chunk
    WHERE document_id IN (
        SELECT id FROM knowledge_document WHERE user_id = #{userId}
    )
    ORDER BY distance
    LIMIT #{topK}
    """)
List<KnowledgeChunk> findSimilar(@Param("userId") String userId,
                                  @Param("queryEmbedding") String queryEmbedding,
                                  @Param("topK") int topK);
```

**收益**: 检索时间从 O(N) 降到 O(log N)

#### 7.6.3 缓存 LLM 响应

**场景**: 相同问题重复询问

**实现**:
```java
@Cacheable(value = "llm-cache", key = "#userId + ':' + #text")
public String chat(String text, ChatClient client, String userId) {
    return client.prompt().user(text).call().content();
}
```

**收益**: 
- 响应时间从 3s 降到 50ms
- 节省 LLM API 费用

### 8.1 架构优势

| 特性 | 实现 | 价值 |
|------|------|------|
| **模块化设计** | 10 个独立业务模块 | 易于扩展和维护 |
| **AI 原生** | Spring AI Function Calling | LLM 自动选择工具,无需硬编码 |
| **多模态支持** | DeepSeek + Agnes | 文本、图像、语音统一处理 |

| **浏览器自动化** | Playwright 持久化上下文 | 登录状态保存,稳定可靠 |
